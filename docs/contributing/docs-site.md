The documentation is a Docusaurus 3 site in `website/`, served from GitHub Pages at [managingwp.github.io/gridpane-alerts-extension](https://managingwp.github.io/gridpane-alerts-extension/). The content stays in the repository's `docs/` directory; the site reads it through `docs.path: '../docs'`. That keeps one home for the pages and keeps `docs/PRIVACY.md` at the path `scripts/package.mjs` requires.

## The contract

- **Front matter on every page.** `title` and `description` are required. The title renders the H1 — do not add a body `#` heading.
- **One sidebar entry per page.** `website/sidebars.ts` lists every page explicitly, in reading order. There is no autogenerated sidebar; an orphan page fails the gate.
- **Links inside docs are relative and keep the extension**: `./installation.md`, `../reference/limits.md`. Never start a link with `/` — the site is served from a subpath, so a root-relative link works locally and 404s on Pages.
- **Links outside docs.** Link a repository file with its GitHub blob URL, and a website with its plain URL. A page that is not part of the site (`docs/PRIVACY.md`) is linked that way too.
- **No body H1.** The front-matter title is the heading; a second H1 breaks the outline and the gate.
- **MDX is not plain Markdown.** `{` and `<` outside a code fence are parsed as JavaScript. Put them in backticks or escape them.
- **Generated blocks are generated.** If a page carries `<!-- BEGIN GENERATED: … -->`, edit the generator, not the page.

## The exclusion

`docs/PRIVACY.md` is the publish source for the canonical policy at [managingwp.io](https://managingwp.io/policies/#gridpane-alerts-archive). It is not a site page: it is excluded in `docusaurus.config.ts` and skipped by the gate with `--exclude PRIVACY.md`. Hosting a second copy would create two canonical policies.

## Local commands

```bash
npm --prefix website install    # first time
npm --prefix website start      # dev server with search
npm --prefix website run build  # production build to website/build
npm --prefix website run typecheck
```

The build is a build step: it installs the Docusaurus toolchain into `website/node_modules` and takes about a minute from cold.

## The publish gate

Copy of the check is `scripts/check-docs-site.sh`. Run it from the repository root after a build:

```bash
npm --prefix website ci
npm --prefix website run build
bash scripts/check-docs-site.sh --site website --repo-root . --docs docs --exclude PRIVACY.md
```

It asserts the config guards (`onBrokenLinks`, `onBrokenAnchors`, `onBrokenMarkdownLinks` all `throw`), pinned Docusaurus versions and a committed lockfile, ignored build output, front matter, the sidebar both ways, relative links, the README budget and its pointer block, the Pages workflow permissions, and the search index.

## Search

The site uses `@easyops-cn/docusaurus-search-local`. It is registered in a top-level `themes` array, and `docsRouteBasePath` must equal `docs.routeBasePath` (`/`); otherwise every result points at a URL that does not exist. `docsDir` points at `../docs` so the index hash scans the real content.

## Publishing

`.github/workflows/docs.yml` builds and deploys on every push to `main` that touches `website/`, `docs/`, `README.md` or the workflow. One manual step is required once: **Settings → Pages → Source: GitHub Actions**. Until that is set, `deploy-pages` fails with *Get Pages site failed*. Do not add `.nojekyll`; the artifact upload bypasses Jekyll.

## A custom domain, later

Not configured. A custom domain changes `url`, `baseUrl` and adds `website/static/CNAME`; it does not change the content tree.
